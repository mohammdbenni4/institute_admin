## What We Did

- **Fixed the previous-recitation bug** (والتسميع السابق بعد دخول الشهر الجديد لا يظهر): the recitation list
  now reads from a **wider fetched window** (`windowFrom = addMonths(month.from, -3) … month.to`), so a
  student's last exam/homework still shows after the month rolls over. `monthRecords` is a derived subset of
  `windowRecords` for the selected month (heatmap/stats/attendance).

### Mobile — refresh + sync/offline UX
- **Refresh button (تحديث)** in the halaqah TopBar: re-pulls halaqah + **students** + records so a
  newly-added student shows up without re-login.
- Replaced the old `UnsyncedBanner` with **`SyncStatus.svelte`**: a small floating pill —
  **green (`cloud_done`) = all synced, amber + count = pending**. Tapping opens a bottom sheet listing each
  pending record.
- Each pending row: **tap to expand a field-by-field old→new diff**, and a **🗑 delete-with-confirm** that
  discards *that one change* (`repo.discardChange`) — locally-created rows are deleted; edited rows revert to
  the server's version (online) or a **captured baseline** (offline). Other pending changes are untouched.
- To make old/new reliable offline, added a **`baseline` snapshot** to `CachedRecord`, captured the first
  time a clean, server-backed record is edited (`repo.snapshotBaseline`).

## Decisions Made
- **APK versionCode = date int** (`YYYYMMDD`, e.g. `20260704`), bumped every build (android/ is regenerated so
  the `build.gradle` bump is re-applied by `sed` each time). Guarantees clean update-installs over prior versions.
- Discarding a change reverts the **whole record** to server/baseline state (not per-field) — matches "delete
  the change". It does **not** trigger an upload of other pending records.
- Attendance: unmarked students get **no record** (rather than a forced حاضر default).
- Deploy settings (adapter-node/PM2/ecosystem) now **belong on origin**, so deploys stop conflicting.

## Key Learnings
- **APK build MUST run `android:fit` + `android:assets` after `cap add`** or the icon + edge-to-edge regress.
  Canonical order: `build:app → cap sync → android:fit → android:assets → gradle`. APK grows ~3.25→3.5 MB once
  icons are baked; verify with `aapt dump badging …apk | grep application-icon` (adaptive `res/…xml`, not a png).
- APK build runs in the worktree's **`frontendMobile/` subdir** (`/root/apk-build/frontendMobile`), not the
  worktree root (no package.json there).
- `svelte.config.js` imports `adapter-node` at module top even for `build:app`, so adapter-node must be
  installed locally too — use `npm ci` to add it **without** rewriting the lock (keeps local == server).
- Headless SSH to the VPS works via the `SSH_ASKPASS` + `setsid -w` trick (no `sshpass`); details in
  machine-local `reference-quran-deploy.md`.
